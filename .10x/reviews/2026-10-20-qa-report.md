# QA report: full-product audit (deployability, usability, module function)

**Date:** 2026-10-20 · **Commit:** 196fa8f · **Method:** clean `npm ci`, every automated suite, then the real stack run locally (Worker + local D1/R2 via `wrangler dev`, staged `.pages-dist` served over HTTPS on a non-loopback hostname so the production sign-in path runs), driven by Playwright as a brand-new shop that signed up through `/signup/`.

## Verdict
Automated gates are green, but **five release blockers** break core front-counter flows for real customers. None of them are caught by the current tests.

## P0: release blockers

| # | Defect | Evidence | Root cause |
|---|---|---|---|
| 1 | **Recording a payment always fails** ("Unsupported payment method"), on both invoices and work orders | POST /api/payments/record body has no `method`, server returns 400 | DOMPurify (via `showModal → safeHtml`) strips `name="method"` as DOM clobbering. Regression since cc3cf13 (Oct 8) |
| 2 | **Add/Edit customer fails silently**, and employee create/edit loses name, title, and role. Vendors, inspection templates, and group chat are also affected | Rendered `<input>` has no `name`. `data.name.trim()` throws in the submit handler | Same sanitizer behavior for `name`, `title`, `role`, `action` |
| 3 | **Payroll page crashes** for every shop: "Cannot access 'state2' before initialization", and the user is left on Employees | pageerror on every visit (desktop + mobile) | `let state = 0` inside `ytdPayForUser` shadows global `state` (filing-overrides.js:322 / legacy.js:4036) |
| 4 | **New shops get another business's identity.** The signup shop name is ignored. Cloud settings are saved as "Your Car Guy", "100 Demo Street, Example City", "555-0100", logo `/assets/reliable-logo.jpg`. Estimates and job cards print it | D1 row `entities(shopsettings/profile)` for the new shop; estimate header in UI | Client seeds the demo profile and PUTs it on first load. | 5 | **Demo data never clears.** New shops see fake ROs, invoices, "$1,128.43 collected", and overdue invoices, and the "Start with a clean shop" prompt never appears | GET /api/onboarding/start returns `{"sampleRecords":0}` | Samples are local-only, so the server count is always 0. ## P1: correctness / compliance
- **Sales tax on labor.** `calculateEstimate` taxes the entire subtotal (labor + parts + supplies). There's no per-line taxable flag or labor-taxability setting. Texas doesn't tax motor-vehicle repair labor; on itemized invoices only parts are taxed (Texas Comptroller pub. 94-113). Example RO: tax $28.84 when parts-only tax would be about $7.42.

## P2: deployability
- The production deploy (`cloudflare-pages.yml` validate job) skips `test:modules` and `lint`, and isn't gated on `ci.yml`. Post-deploy smoke checks only warn.
- ESLint excludes `legacy.js` and `filing-overrides.js`, which is where defects 1–3 live. There's no browser-level smoke test, so 236/236 unit tests passed with three core flows broken.
- `npm run dev:worker` fails without Cloudflare credentials (`send_email.remote: true` and the `ai` binding are remote-only), so a new developer can't run the API offline.
- auto-merge.yml enables auto-merge for Cursor-bot PRs and dispatches a production deploy. Confirm branch protection requires CI plus review.
- Hygiene: stray files (`r.text()).then(console.log)`, `_tmp_stripe_scan.txt`, duplicate `mechpro-*`/`shopcrank-*` screenshots); unreferenced `assets/index-BNolS2h_.js` + `.css` (~470 KB) ship to Pages; `npm start` runs the mock server that returns an admin session; there's no `.gitattributes`; migration prefixes are duplicated.
- `GOOGLE_REDIRECT_ORIGIN` still points to yourcarguy806.com (known pending cutover).

## P3: usability
- Intake: Convert needs 4 walk-around photos with no click feedback. The estimate step allows one labor line and no parts, and its total doesn't update live. Email is required at the counter.
- The floating Help button covers the "Accounting" nav item at 1440×900. There's a stray empty pill beside Assistant. "New Customer Intake" appears twice on Home.
- Invoices shows work-order KPIs, and the demo "PAID" invoice lists 0 payments.
- The status pill stays "Online" while offline.
- OBD bay / AI workbench call `/api/diagnostics/j2534/*` on the hosted web app and get repeated 405s.
- Messaging defaults to `enabled: true` with endpoint `https://httpbin.org/post` and shows "Shop messaging service active". CSP blocks it today, but it's misleading and becomes a data leak if CSP is ever relaxed.
- The signup placeholder shows "Your Car Guy". The login footnote is in the wrong font size. The lucide icon `cloud-check` is missing. Completing an RO gives no confirmation toast.
